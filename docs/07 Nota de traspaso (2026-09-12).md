## 3. Cómo se reconstruye el entorno (≈ 15 min; detalle en `ops/BOOTSTRAP.md` del repo)

1. `git clone` del repo (o `git clone gpm-artefacto_<fecha>.bundle`) → `build30/` (generador), `artefacto/engine` (`npm i`), `artefacto/app` (`pnpm install --frozen-lockfile`); Playwright con Chromium para `smoke.mjs`. Requisitos del generador: Python 3.11, `openpyxl 3.1.5`, LibreOffice headless, pdfplumber, poppler.
2. Referencias en `/root/gpm13/verif/` y `refs/`: `gen_v20_calc.xlsx` (R1), `Modelo_FV_5MWp_GPM_v3.1_r3_calc.xlsx` y `…Resumen_Directorio_v3.1_r3_calc.xlsx` (de `referencias_regresion_v3.1.zip`).
3. Libro: `REF=<calc anterior> ALLOW="N_Controles,N_Controles_OK,N_Por_Confirmar_Esperado,N_Por_Confirmar[,nombres que cambian por diseño]" ./pipeline.sh Modelo_FV_5MWp_GPM_v3.1_rN` → build, `check_estilo` 0, `check_print` ✔, recálculo LibreOffice, `check_errors` (sólo los `#N/A` de `00_Portada!D103:AD104`), `regress30` por etiqueta, `shadow30 --blocks`, `inject_values`. Resumen: `MODEL=<calc del libro> ./pipeline_res.sh Modelo_FV_5MWp_Resumen_Directorio_v3.1_rN` (`--same` 0 diferencias).
4. Artefacto: `extract_model.py RAW CALC artefacto/data` → `extract_book.py` → `cp data/book.json app/src/model/book_v31.json` → `bash scripts/release.sh "<etiqueta>"` (verify 91.546/0 → `make-oracle.py` + `make-externo.py` → TIR ≡ Excel → live/format → tsc → build de ediciones + `check:exclusion` → smoke 22/22 × 2 → SHA → `publicados/` → `out/candidato/`). Publicar primero los **candidatos** (herramienta Artifact con `url` + `label`); las URL oficiales sólo con la palabra «promover» de Jorge.
5. Cruce aleatorio motor ↔ LibreOffice: `ENGINE_DIR=… python3 build30/crosscheck_engine.py RAW out N SEED` (~25 s/muestra).

## 4. Cómo se renderiza y se prueba desde el Mac de Jorge (lo que funciona, 11/12-sep-2026)

- Copiar el xlsx con **nombre único** a `_borrador_v3.1/pruebas/…_prueba.xlsx` (`SendUserFile` → `device_commit_files`; SHA-256 con `shasum` por `device_bash`). **Avisar a Jorge antes de abrir Excel** y comprobar que Excel no tiene libros abiertos (AppleScript `count of workbooks`).
- Tercer motor: Excel MCP `open_workbook` → AppleScript `calculate` → `value of range "B57:DH72" of sheet "Motor_Sens"` (16 salidas × 111 casos), `"B5:DH34"` (parámetros), `"B4:DH4"` (nombres); nombres definidos con `value of (reference range of named item "X" of active workbook)` (`range "X" of workbook` falla). Escribir el resultado a un `.txt` en `pruebas/` (`open for access … write … as «class utf8»`) y traerlo con `device_stage_files`; comparar con `motor.json` (AppleScript devuelve 12 cifras → tolerancia relativa 5e-11).
- Render: `activate object sheet "00_Portada"` → Excel MCP `export_pdf` (exporta el libro completo pese al nombre; sobre un PDF existente puede tardar > 60 s y la herramienta expira aunque termine) → si devuelve «Parameter error −50», AppleScript `save active sheet of wb in <ruta> as PDF file format` (a veces escribe en `~/Library/Containers/com.microsoft.Excel/Data/`: copiar con `do shell script cp`) → `close_workbook(save=false)` → SHA de la copia igual → `device_stage_files` → `check_render.py`.
- `device_bash` es una VM Linux sin `osascript`; `mv`/`cp` dentro de la carpeta montada sí funcionan (así se hacen las sustituciones y `superadas/`). `get_range_values` del MCP devuelve vacío: leer siempre con AppleScript.
- **AutoSave manda:** los libros del raíz no se abren con el conector; las pruebas sólo en copias `_prueba`.
- Reglas de Jorge: **avisar antes de abrir Excel en su Mac; nunca capturas de su pantalla (capturas en el contenedor con Playwright); nunca sobrescribir un archivo que tenga abierto; copias borrador con nombre único; los entregables se sustituyen sólo con su aprobación explícita y lo sustituido va a `superadas/` (Claude no borra); Claude no recibe tokens ni contraseñas** (el push a GitHub se hace desde su Mac con `gh`, ya autenticado).
